What the current implementation covers

The app is built around the current MVP model: jobs contain script lines, invite links bring performers into a guest session, recordings are submitted per line, and the requester reviews and exports the result. The production backend is being shaped as a Cloudflare Worker with Supabase metadata and R2 audio storage.

iOS requester workspace

Account registration/login, job list management, CSV/XLSX script import, job creation wizard, video asset attachment, invite link management, progress tracking, review, reference sharing, and ZIP export.

iOS performer workspace

Invite opening, accept/decline, optional performer account creation, targeted line list, notes from the requester, recording controls, local preview, upload, progress state, and shared reference audio playback.

Backend state

The detailed app flow is represented in the legacy FastAPI backend. The current Worker implements project creation, line creation, one-take upload, review fetch, audio download, and health checks against Supabase and R2.

Requester workflow in detail

The requester side is the control room. It turns a spreadsheet or line list into a trackable recording job and keeps every delivery decision tied to the exact line that needs it.

Performer workflow in detail

The performer side is intentionally narrower. It shows what this performer needs to record, the context around those lines, and the feedback or reference takes needed to deliver the next useful submission.

How work moves between both sides

TakeFlow keeps the handoff explicit: the requester creates structure, the performer records against that structure, and review decisions return to the performer as line-level state.

Where the model is heading

The future direction is scene-centered: one shared scene video, line-level assignments, multiple takes, and only approved reference takes exposed to other performers.
